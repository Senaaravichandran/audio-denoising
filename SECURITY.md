# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 2.0.x   | :white_check_mark: |
| 1.x.x   | :x:                |

## Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability in AudioClarity, please report it responsibly.

### How to Report

1. **Email**: Send details to [security@audioclarity.dev](mailto:security@audioclarity.dev)
2. **Include**:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### What to Expect

- **Acknowledgment**: Within 24 hours
- **Initial Assessment**: Within 48 hours
- **Regular Updates**: Every 72 hours until resolved
- **Resolution**: Security patches will be prioritized

### Security Best Practices

When using AudioClarity:

- Keep dependencies updated
- Use environment variables for API keys
- Run with minimal required permissions
- Monitor for unusual activity
- Use HTTPS in production

### Responsible Disclosure

We appreciate security researchers who:

- Allow reasonable time for fixes before public disclosure
- Avoid accessing or modifying user data
- Don't perform attacks against our infrastructure
- Report vulnerabilities in good faith

Thank you for helping keep AudioClarity secure!
